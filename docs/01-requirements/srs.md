# 소프트웨어 요구사항 명세서 (SRS)

> 상태: **Must 확정** (Should·Could는 초안) · 최종 수정일: 2026-11-27
> 구성은 IEEE 830 / ISO 29148을 간소화했다.

## 1. 개요
- 목적: 캐디 수입 관리 웹앱의 기능·비기능 요구사항을 정의한다.
- 근거 문서: `../00-overview/project-charter.md`, `../00-overview/glossary.md`, `open-questions.md`
- 사용자: 지인 캐디 소수(각자 계정), 주로 휴대폰으로 퇴근 후 집에서 기록 (Q-001, Q-006, Q-007)

## 2. 우선순위 기준 (MoSCoW)
| 등급 | 의미 |
|---|---|
| **Must** | MVP에 반드시 포함 |
| **Should** | 중요하지만 MVP 이후 가능 |
| **Could** | 여유 있으면 |
| **Won't** | 이번 범위에서 제외 (기록만) |

## 3. 기능 요구사항 (Functional Requirements)
> 작성 규칙: "시스템은 ~해야 한다" 형태, 하나의 요구사항에 하나의 기능, 검증 가능하게.
> 상세가 필요한 요구사항은 `../templates/requirement.md` 형식으로 본문 하단에 붙인다.

## 5. 인수 조건 (Acceptance Criteria) — Must 요구사항
> 형식: **Given**(상황) / **When**(행동) / **Then**(결과). 각 조건에 `AC-요구사항번호-순번` ID를 붙이고, 테스트 케이스는 이 ID를 참조한다.
> Claude가 제안한 가정(금액 범위, 골프장 이름 중복 금지, 평균 반올림, 터치 요소 44px, 비용 기준 10명 등)은 2026-11-26 사용자가 일괄 승인했다.

### 공통 입력 규칙
| 항목 | 규칙 | 근거 |
|---|---|---|
| 날짜 | 필수. 과거·오늘·미래 날짜 모두 허용 | Q-019 |
| 부 | 필수. 1부 / 2부 / 3부 중 하나 | Q-014 |
| 골프장 | 필수. 본인이 등록한 골프장 중 숨김 처리되지 않은 것 | FR-004, Q-018 |
| 캐디피 | 필수. 원 단위 정수, **1원 이상 1,000,000원 이하** | NFR-005 |
| 오버피 | 선택(비우면 0원). 원 단위 정수, **0원 이상 1,000,000원 이하** | FR-002 |
| 나인추가 횟수 | 선택(기본 0회). **1부에서만** 입력 가능. 정수 **0~2회** | FR-008, Q-022, Q-023 |
| 나인추가 금액 | 횟수가 1 이상일 때만 입력. 기본값 = 캐디피 ÷ 2 (원 단위 내림) × 횟수. 직접 수정 가능, 원 단위 정수 **1원 이상 1,000,000원 이하** | FR-008, Q-021 |
| 중복 | 같은 사용자의 같은 날짜·같은 부 라운드는 하나만 존재 | Q-017 |
| 라운드 수입 | 캐디피 + 나인추가 금액 + 오버피 | FR-008 |
| 환산 라운드 수 | 라운드 1건 = 1 + 0.5 × 나인추가 횟수 (예: 1부 + 나인추가 1회 = 1.5라운드). 저장은 정수(횟수)로 하고 표시할 때만 계산 | Q-024, NFR-005 |

### FR-001 라운드 등록
- **AC-001-1** Given 골프장이 1개 이상 등록된 사용자 / When 날짜·부·골프장·캐디피를 입력하고 저장 / Then 라운드가 저장되고 해당 날짜의 달력·월 통계에 즉시 반영된다.
- **AC-001-2** Given 입력 폼 / When 날짜·부·골프장·캐디피 중 하나라도 비우고 저장 / Then 저장되지 않고 비어 있는 항목 옆에 오류 메시지가 표시된다.
- **AC-001-3** Given 입력 폼 / When 캐디피에 0, 음수, 소수, 1,000,000 초과 값을 입력하고 저장 / Then 저장되지 않고 허용 범위를 안내한다.
- **AC-001-4** Given 미래 날짜 / When 미래 날짜로 라운드를 저장 / Then 정상 저장된다. (Q-019)
- **AC-001-5** Given 등록된 골프장이 하나도 없는 사용자 / When "라운드 추가"를 누름 / Then 골프장 등록 화면으로 안내한다.

### FR-002 오버피
- **AC-002-1** Given 입력 폼 / When 오버피를 비워두고 저장 / Then 오버피 0원으로 저장된다.
- **AC-002-2** Given 입력 폼 / When 오버피 30,000을 입력하고 저장 / Then 라운드 수입 = 캐디피 + 30,000으로 집계된다.
- **AC-002-3** Given 입력 폼 / When 오버피에 음수·소수·1,000,000 초과 값을 입력 / Then 저장되지 않고 허용 범위를 안내한다.

### FR-003 라운드 수정·삭제
- **AC-003-1** Given 저장된 라운드 / When 캐디피를 바꿔 저장 / Then 변경값이 저장되고 달력·통계 합계가 다시 계산된다.
- **AC-003-2** Given 저장된 라운드 / When 날짜나 부를 바꿔서 이미 있는 날짜·부와 겹치게 저장 / Then 저장되지 않고 중복 안내가 표시된다. (Q-017)
- **AC-003-3** Given 저장된 라운드 / When 삭제를 누름 / Then "삭제할까요?" 확인 창이 뜨고, 확인을 누를 때만 삭제된다. 취소하면 아무것도 바뀌지 않는다. (Q-020)
- **AC-003-4** Given 라운드 삭제 완료 / When 달력·통계를 봄 / Then 삭제된 라운드는 합계에서 빠져 있다.

### FR-004 골프장 관리
- **AC-004-1** Given 사용자 / When 골프장 이름과 기본 캐디피를 입력해 추가 / Then 본인의 골프장 목록에 나타난다.
- **AC-004-2** Given 이미 "OO CC"가 있음 / When 같은 이름으로 또 추가 / Then 저장되지 않고 중복 안내가 표시된다.
- **AC-004-3** Given 골프장 목록 / When 한 골프장을 기본 골프장으로 지정 / Then 이후 라운드 입력 폼에 그 골프장이 처음 선택돼 있다. 기본 골프장은 한 번에 하나뿐이다.
- **AC-004-4** Given 라운드 기록이 있는 골프장 / When 삭제(숨기기)를 누름 / Then 골프장 목록과 라운드 입력 선택지에서 사라지지만, 지난 라운드·통계에는 그 골프장 이름이 그대로 표시된다. (Q-018)
- **AC-004-5** Given 기본 골프장으로 지정된 골프장 / When 숨기기 / Then 기본 골프장 지정이 해제된다.
- **AC-004-6** Given 라운드 기록이 없는 골프장 / When 삭제 / Then 완전히 삭제된다.
- **AC-004-7** Given 사용자 A의 골프장 / When 사용자 B가 골프장 목록을 봄 / Then A의 골프장은 보이지 않는다. (Q-016)

### FR-005 하루 여러 라운드 (1부/2부/3부)
- **AC-005-1** Given 11/26에 라운드가 없음 / When 11/26 라운드 입력 폼을 엶 / Then 부가 1부로 채워져 있다.
- **AC-005-2** Given 11/26 1부가 있음 / When 11/26 라운드 입력 폼을 엶 / Then 부가 2부로 채워져 있다.
- **AC-005-3** Given 11/26 1부가 있음 / When 11/26 1부로 또 저장 / Then 저장되지 않고 "이미 1부 기록이 있습니다" 안내가 표시된다. (Q-017)
- **AC-005-4** Given 11/26 1·2·3부가 모두 있음 / When 11/26에 라운드 추가 시도 / Then 더 추가할 수 없다고 안내한다.
- **AC-005-5** Given 11/26 1부와 2부 / When 달력·목록을 봄 / Then 두 라운드가 부 순서대로 따로 표시된다.

### FR-006 골프장별 기본 캐디피
- **AC-006-1** Given A CC 기본 캐디피 150,000, B CC 기본 캐디피 160,000 / When 입력 폼에서 A CC 선택 / Then 캐디피가 150,000으로 채워진다.
- **AC-006-2** Given 위 상황 / When 골프장을 B CC로 바꿈 / Then 캐디피가 160,000으로 바뀐다.
- **AC-006-3** Given 자동으로 채워진 캐디피 / When 사용자가 직접 다른 금액으로 고쳐 저장 / Then 고친 금액으로 저장되고, 골프장의 기본 캐디피는 바뀌지 않는다.

### FR-007 기본 캐디피 변경 시 지난 기록 보존
- **AC-007-1** Given A CC 기본 캐디피 150,000으로 기록한 라운드 10건 / When A CC 기본 캐디피를 160,000으로 변경 / Then 기존 10건의 캐디피는 150,000 그대로이고 월 통계도 바뀌지 않는다.
- **AC-007-2** Given 위 변경 후 / When A CC로 새 라운드 입력 / Then 캐디피가 160,000으로 채워진다.
- **AC-007-3** Given 캐디피 150,000 + 나인추가 75,000으로 기록한 라운드 / When 골프장 기본 캐디피를 160,000으로 변경 / Then 그 라운드의 나인추가 금액은 75,000 그대로다.

### FR-008 나인추가
- **AC-008-1** Given 1부, 캐디피 160,000 / When 나인추가 횟수를 1로 선택 / Then 나인추가 금액이 80,000으로 채워진다.
- **AC-008-2** Given 1부, 캐디피 160,000 / When 나인추가 1회 + 오버피 20,000으로 저장 / Then 라운드 수입 260,000 (160,000 + 80,000 + 20,000), 환산 라운드 수 1.5로 집계된다.
- **AC-008-3** Given 1부, 캐디피 160,000 / When 나인추가 횟수를 2로 선택 / Then 나인추가 금액이 160,000으로 채워지고, 환산 라운드 수는 2.0이다.
- **AC-008-4** Given 자동으로 채워진 나인추가 금액 80,000 / When 사용자가 70,000으로 고쳐 저장 / Then 70,000으로 저장된다.
- **AC-008-5** Given 나인추가 금액을 직접 고치지 않은 상태 / When 캐디피를 150,000으로 바꿈 / Then 나인추가 금액이 75,000 × 횟수로 다시 채워진다. (직접 고친 뒤에는 자동으로 바뀌지 않는다)
- **AC-008-6** Given 2부 또는 3부 입력 폼 / When 폼을 봄 / Then 나인추가 입력란이 보이지 않거나 비활성화돼 있다. (Q-022)
- **AC-008-7** Given 나인추가가 있는 1부 라운드 / When 부를 2부나 3부로 바꿔 저장 / Then 저장되지 않고 "나인추가는 1부에만 기록할 수 있습니다" 안내가 표시된다.
- **AC-008-8** Given 나인추가 0회 / When 저장 / Then 나인추가 금액은 0원으로 저장된다.
- **AC-008-9** Given 캐디피 155,555 / When 나인추가 1회 선택 / Then 나인추가 금액이 77,777로 채워진다 (원 단위 내림).
- **AC-008-10** Given 1부 입력 폼 / When 나인추가 횟수를 3 이상으로 입력 / Then 선택할 수 없거나 저장되지 않고 "나인추가는 최대 2회까지" 안내가 표시된다.

### FR-010 달력
- **AC-010-1** Given 이번 달 라운드 기록 / When 달력 화면을 엶 / Then 이번 달이 표시되고, 라운드가 있는 날짜마다 라운드 수와 수입 합계가 보인다.
- **AC-010-2** Given 달력 / When 이전/다음 달로 이동 / Then 해당 달의 기록이 표시된다.
- **AC-010-3** Given 달력 / When 라운드가 있는 날짜를 누름 / Then 그날의 라운드 목록(부, 골프장, 캐디피, 나인추가, 오버피)이 보이고, 각 라운드를 수정·삭제할 수 있다.
- **AC-010-5** Given 11/26 1부 + 나인추가 1회 / When 달력을 봄 / Then 11/26 칸에 1.5라운드와 수입 합계가 표시된다.
- **AC-010-4** Given 달력 / When 라운드가 없는 날짜를 누름 / Then 그 날짜로 라운드 입력 폼이 열린다.

### FR-011 월별 통계
- **AC-011-1** Given 11월 라운드 3건 (캐디피 150,000·150,000·160,000 / 오버피 0·20,000·30,000) / When 11월 통계를 봄 / Then 총수입 510,000, 캐디피 합계 460,000, 오버피 합계 50,000, 라운드 수 3, 라운드당 평균 170,000이 표시된다.
- **AC-011-2** Given 라운드가 없는 달 / When 통계를 봄 / Then 총수입 0, 라운드 수 0이 표시되고 평균은 "-"로 표시된다. (0으로 나누기 오류 없음)
- **AC-011-3** Given 라운드당 평균이 나누어떨어지지 않음 / When 통계를 봄 / Then 원 단위로 반올림해 표시한다.
- **AC-011-4** Given 이번 달에 미래 날짜 라운드가 있음 / When 이번 달 통계를 봄 / Then 미래 날짜 라운드도 포함해 집계한다. (Q-019)
- **AC-011-5** Given 12월 라운드 2건: ① 1부 캐디피 160,000 + 나인추가 1회 80,000 + 오버피 20,000, ② 2부 캐디피 160,000 / When 12월 통계를 봄 / Then 총수입 420,000, 캐디피 합계 320,000, 나인추가 합계 80,000 (1회), 오버피 합계 20,000, 라운드 수 2.5, 라운드당 평균 168,000 (420,000 ÷ 2.5)이 표시된다.

### FR-040 카카오 로그인
- **AC-040-1** Given 처음 방문한 사용자 / When "카카오로 시작하기"를 눌러 카카오 인증 완료 / Then 계정이 자동 생성되고 홈 화면으로 이동한다.
- **AC-040-2** Given 이미 가입한 사용자 / When 다시 카카오 로그인 / Then 새 계정이 생기지 않고 기존 데이터가 그대로 보인다.
- **AC-040-3** Given 로그인한 사용자 / When 로그아웃 / Then 로그인 화면으로 이동하고, 뒤로 가기를 해도 데이터 화면이 보이지 않는다.
- **AC-040-4** Given 로그인하지 않은 상태 / When 앱의 어떤 화면 주소로 직접 접속 / Then 로그인 화면으로 이동한다.
- **AC-040-5** Given 카카오 인증 화면 / When 사용자가 동의를 취소 / Then 로그인 화면으로 돌아오고 오류 안내를 표시한다.

### NFR (Must)
- **AC-N001-1** (사용성) 폭 360px 화면에서 모든 화면이 가로 스크롤 없이 표시된다.
- **AC-N001-2** (사용성) 버튼·입력창 등 누르는 요소는 최소 44×44px이다.
- **AC-N001-3** (사용성) 기본 골프장이 지정되고 **서버가 응답 가능한 상태(깨어난 뒤)**에서 "라운드 추가 → 오버피 입력 → 저장"이 30초 안에 끝난다 (사용자 테스트로 확인). 서버가 깨어나는 대기 시간은 NFR-002 예외로 다룬다 (Q-025, ADR-0002).
- **AC-N003-1** (보안) 사용자 B가 사용자 A의 라운드·골프장 ID로 조회·수정·삭제 요청을 직접 보내면 거부된다 (화면이 아니라 서버/DB에서 막는다). 자동화 테스트로 검증.
- **AC-N003-2** (보안) 목록·달력·통계·CSV 어디에도 다른 사용자의 데이터가 섞이지 않는다.
- **AC-N004-1** (신뢰성) 저장 완료 메시지가 뜬 라운드는 새로고침·재로그인 후에도 남아 있다.
- **AC-N004-2** (신뢰성) 데이터 백업 방법이 하나 이상 있다 (DB 백업 또는 정기 내보내기). 구체 방식은 설계에서 결정.
- **AC-N005-1** (정확성) 금액은 DB에 정수형으로 저장된다. 소수점 계산이 없다.
- **AC-N005-2** (정확성) 월 통계의 총수입은 그 달 라운드별 (캐디피 + 나인추가 금액 + 오버피)를 직접 더한 값과 항상 같다.
- **AC-N007-1** (비용) 사용자 10명, 1인당 하루 3라운드 기준으로 1년 운영해도 모든 서비스가 무료 티어 한도 안에 있다. 설계 단계에서 각 서비스의 무료 한도를 ADR에 기록한다.
