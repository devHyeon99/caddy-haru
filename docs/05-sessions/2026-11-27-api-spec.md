# 세션 로그: REST API 명세 작성

> 날짜: 2026-11-27 · 단계: Phase 2

## 목표
SRS의 Must 요구사항과 `data-model.md`를 기준으로 `docs/02-design/api-spec.md`를 작성한다. 범위는 인증(카카오 로그인·로그아웃·내 정보), 골프장, 라운드, 월·연 통계, CSV, health다. 각 API에 메서드·경로·요청/응답 JSON·상태 코드·검증 규칙·FR/AC ID를 적는다. 다른 사용자의 리소스 ID로 요청했을 때 403과 404 중 무엇을 줄지 제안하고, 에러 응답 공통 형식을 정한다.

## 한 일
- CLAUDE.md, PROGRESS.md, SRS, data-model, architecture(§3~§6·§10), ADR-0005, glossary를 읽었다.
- `api-spec.md`를 작성했다(상태: 검토중).
  - §1 공통 규칙: `/api` 기준 주소, camelCase, 금액은 JSON 정수, 날짜는 `YYYY-MM-DD`, 환산 라운드 수는 `roundHalfUnits` 정수(NFR-005), 모르는 필드·`userId`가 오면 400, 쿠키 인증, Origin·프록시 비밀이 틀리면 403, `Cache-Control: no-store`(AC-040-3), `X-Request-Id`.
  - §2 상태 코드 원칙. **400 = 형식·범위(DTO), 422 = 업무 규칙(필드 조합·상태), 409 = DB 유니크 충돌.** architecture §3.2의 예외 매핑을 그대로 따른다. 사용자가 적은 코드 목록에는 422가 없었지만, architecture에서 이미 정한 구분이라 유지했다. 에러 형식(ADR-0008)과 에러 코드 15개도 정했다.
  - §3 남의 리소스: **404를 제안했다**(ADR-0005와 같은 방향). 근거는 존재 여부 노출(순번 ID 열거), 한 번의 `WHERE id AND user_id` 쿼리, 완전 분리의 의미, RFC 9110 허용이다. 본문의 `golfClubId`가 남의 것일 때도 404를 준다. "없는 ID"와 응답을 깊은 비교로 똑같이 맞추는 테스트를 추가했다. 403은 요청 출처에만 쓴다.
  - §4 엔드포인트 17개. Must 15개, Should 2개(E2 연 통계 FR-030·012, F1 CSV FR-031)는 Must 구현 뒤 만든다. FR-041(계정 삭제)은 SRS가 초안이라 넣지 않았다.
  - 인증: logout은 `@Public()` + 항상 204, 콜백은 항상 302(`/login?error=`), `me`는 카카오 회원번호를 노출하지 않는다.
  - 골프장: 목록은 숨긴 것 제외, PATCH로 기본 지정(트랜잭션), DELETE는 `200 { result: "hidden" | "deleted" }`. 숨긴 골프장을 수정·삭제하면 404. 단건 GET은 만들지 않았다(`:id` 라우트 수를 줄임).
  - 라운드: 응답에 `golfClub { id, name, hidden }`와 파생 값 `income`·`roundHalfUnits`를 넣었다. PATCH는 기존 값과 합친 결과 전체를 검증한다. `nineExtFee`를 생략했을 때의 서버 규칙을 정했다. 기본 캐디피·부 자동 선택은 SPA가 한다(서버가 몰래 채우지 않음 → FR-007).
  - 통계: E1 = `summary` + 달력 `days`(AC-011-5 예시 그대로), 평균은 0건이면 `null`(AC-011-2). E2는 `months` 12개 고정.
  - CSV: UTF-8 BOM, 기간 최대 366일, **CSV 수식 주입 방지**(골프장 이름이 `=`·`+`·`-`·`@`로 시작하면 이스케이프).
  - §11 테스트 연결, §12 요구사항 → API 추적표.
- `ADR-0008-api-error-format.md`를 작성했다. NestJS 기본 형식, RFC 9457, 자체 형식을 비교한 뒤 자체 형식으로 정했고, 사용자가 승인했다.
- `architecture.md`를 동기화했다. §3.2 예외 매핑에 403(요청 출처) 행과 ADR-0008 링크를 추가했고, §10과 변경 이력도 고쳤다.
- Q-027을 등록했다. 날짜에 2000~2099 기술적 허용 범위를 둘지 묻는 질문이다. 사용자가 같은 세션에서 **승인**해 해결했다.

## 결정 사항
- 남의 리소스 ID → **404** (ADR-0005를 api-spec §3에서 구체화했다. 응답은 없는 ID와 구분되지 않는다)
- ADR-0008 에러 형식 `{ error: { code, message, fields?, requestId } }` — **사용자 승인** (같은 세션)
- 설계 선택(api-spec에 기록): 골프장 DELETE는 200 + 결과, logout은 공개 + 204, CSV 기간은 최대 366일, 골프장 단건 GET은 만들지 않음
